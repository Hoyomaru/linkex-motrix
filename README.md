# Linkex Motrix

Linkexの共有ファイルを、自分のストレージに保存 → Motrixでダウンロード → 完全削除、の流れで落とすEdge拡張機能。

要件と調査結果は [linkex-research.md](linkex-research.md)、運営からの回答は [docs/support-replies.md](docs/support-replies.md)。

## ビルド

```
npm install
npm run build
```

`dist/` に拡張機能ができる（`content.js` だけは別の設定 `vite.content.config.ts` で1ファイルにまとめてビルドする）。

## Edgeへの読み込み

1. `edge://extensions` を開く
2. 左下の「開発者モード」をオンにする
3. 「展開して読み込み」で `dist` フォルダを選ぶ
4. ビルドし直したら、拡張機能の一覧で「再読み込み」を押し、開いている共有ページも再読み込みする

## 使い方

1. ツールバーのアイコン →「専用ページを開く」
2. 設定にMotrixの接続先・RPCシークレット・保存先を入れて「保存」→「接続テスト」
3. キューに共有リンクを登録する（どちらでも）
   - 専用ページの「キュー」欄に共有URLを1行に1つずつ貼って「キューに追加」
   - Linkexの共有ページ右下のパネルで「全部キューに追加」または「選んで追加」
4. 「開始」を押す（共有ページのパネルは「追加したら開始する」がオンなら自動で始まる）

Linkexにはログインしておくこと。処理中はLinkexのドライブが固定タブで自動的に開く（裏にあってよい）。

### 設定

| 項目 | 初期値 | 内容 |
|---|---|---|
| Motrixの接続先 | `http://127.0.0.1:16800/jsonrpc` | Motrix（aria2）のRPC |
| RPCシークレット | 空 | Motrixの「設定 → 詳細」の値 |
| 基準フォルダ | 空（Motrixの既定） | この下に `共有名\共有内のフォルダ` を作る |
| APIを呼ぶ間隔 | 300ミリ秒 | 一時的な速度制限を避けるため |
| 同時ダウンロード数 | 3 | Motrixで同時に落とす数 |
| 転送量の上限で一時停止 | オン | 公式Web版と同じ動き。運営の回答（docs/support-replies.md）に従うならオフ |

## 処理の流れ（1件ごと）

1. 同じ中身をダウンロード済みなら飛ばす（ハッシュで判定。「落とし直す」で強制できる）
2. 保存前の自分のファイル一覧を記録 → 共有から保存（file/copy）→ 完了待ち
3. 保存前になかった、名前とサイズが一致するファイルを「自分が作ったコピー」とみなす
4. ダウンロードURLを発行してMotrixへ渡す
5. すぐにゴミ箱へ移して完全削除（保存前からあったファイルは絶対に消さない）。URLは削除後も使える
6. Motrixでの完了を見届けたら「完了」。失敗したら共有から保存し直して再試行（最大3回、途中まで落とした分は続きから）

- Motrixにつながらないときは、件ごとの失敗に数えず全体を一時停止する
- キューは拡張機能内に保存される。Edgeを閉じても続きから再開でき、Service Workerは1分ごとに起きて処理を続ける
- 何が起きたかは専用ページの「処理ログ」に残る（最新300件）

## しくみ

- **Service Worker**（`src/background/`）が全体の指示役。タブの中ではタイマーを回さないので、タブが裏に回っても止まらない
  - `engine.ts`：キューの処理（保存 → URL → Motrix → 完全削除 → 完了の見届け）
  - `enqueue.ts`：共有の中身を読んでキューに追加
  - `linkex-tab.ts` / `linkex-bridge.ts`：Linkexの固定タブで、ページ内の通信部品を `import()` で取り出してAPIを呼ぶ。署名やログイン情報はページ自身が付ける
  - `motrix.ts`：aria2 の JSON-RPC
- **専用ページ**（`dashboard.html`）とポップアップ（`popup.html`）
- **共有ページのパネル**（`src/content/share-page.ts`）：Shadow DOM の中に描くので、Linkexの画面を崩さない
