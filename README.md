# Linkex Motrix

Linkexの共有ファイルを、自分のストレージに保存 → Motrixでダウンロード → 完全削除、の流れで落とすEdge拡張機能。

いまは**段階1**。共有URLを貼って「開始」を押すと、1件ずつ「保存 → URL発行 → Motrixへ渡す → 完全削除」を自動で通す。要件と調査結果は [linkex-research.md](linkex-research.md)。

## 処理の流れ（1件ごと）

1. 同じ中身をダウンロード済みなら飛ばす（ハッシュで判定）
2. 保存前の自分のファイル一覧を記録 → 共有から保存（file/copy）→ 完了待ち
3. 保存前になかった、名前とサイズが一致するファイルを「自分が作ったコピー」とみなす
4. ダウンロードURLを発行してMotrixへ渡す（保存先: 基準フォルダ\共有名\共有内のフォルダ）
5. すぐにゴミ箱へ移して完全削除（保存前からあったファイルは絶対に消さない）
6. Motrixでの完了を見届けたら「完了」。失敗したら共有から保存し直して再試行（最大3回）

キューは拡張機能内に保存されるので、Edgeを閉じても続きから再開できる。Service Workerは1分ごとに起きて処理を続ける。

## ビルド

```
npm install
npm run build
```

`dist/` に拡張機能ができる。開発中は `npm run watch` で変更のたびに作り直せる。

## Edgeへの読み込み

1. `edge://extensions` を開く
2. 左下の「開発者モード」をオンにする
3. 「展開して読み込み」で `dist` フォルダを選ぶ
4. ビルドし直したら、拡張機能の一覧で「再読み込み」を押す

## 使い方（段階0）

1. ツールバーのアイコン → 「専用ページを開く」
2. 設定にMotrixの接続先・RPCシークレット・保存先を入れて「保存」→「接続テスト」
3. Linkexにログインしていれば、容量と転送量が表示される（Linkexの固定タブが裏で自動的に開く）

## しくみ

- **Service Worker**（`src/background/`）が全体の指示役。タブの中ではタイマーを回さないので、タブが裏に回っても止まらない
- **Linkexの固定タブ**：APIを呼ぶときだけ、ページ内の通信部品を `import()` で取り出して使う（`linkex-bridge.ts`）。署名やログイン情報はページ自身が付ける
- **Motrix**：aria2 の JSON-RPC にダウンロードURLを渡す（`motrix.ts`）
